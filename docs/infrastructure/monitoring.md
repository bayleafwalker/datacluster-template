# Monitoring & Alerting

## Metrics sources

| Component | Endpoint | Notes |
|-----------|----------|-------|
|Node Exporter|`/metrics` on each node|CPU, memory, disk, network|
|Kube State Metrics|`/metrics`|Object counts, pod status|
|Spark Driver & Executors|`http://<podIP>:8090/metrics`|Enabled via JMX Exporter sidecar|
|Spark History Server|`/metrics` (optional)|Completed-app metrics|

Prometheus is installed via `kube-prometheus-stack` HelmRelease.  
A `ServiceMonitor` called **spark-metrics** is auto-generated by Spark Operator when `monitoring.prometheus` is set in the `SparkApplication` spec.

## Dashboards

* **Kubernetes / USE Method** – CPU, memory, network saturations.  
* **Spark Application Summary** – active stages, shuffle read/write, executor metrics.  
* **Structured Streaming** – input rows/sec, processed rows/sec, micro-batch latency.

Dashboards reside in `infrastructure/monitoring/grafana-dashboards/`.

## Alerts (PrometheusRule)

* *High driver failure rate* – `sum(rate(spark_driver_failed_executors...)) > 0.1`.  
* *Executor OOM killed* – fires if memory % > 95 % for 5 m.  
* *Cluster CPU > 80 %* – alert to Slack or Email.

Tune thresholds as real workloads arrive.
